# Wavebird Python publisher integration

The versioned `wavebird-publisher-server` wheel connects a Python application to the Wavebird `/v1` lifecycle. Banner, Native and Clip use the same saved-project placement, consent, timing, generation and reporting contract. Test activity is nonpayable. Keep the Server Key and Preference Secret on the server. Production use requires a separately approved project and production key; the package cannot grant that authority.

Install the exact wheel from its matching published release and verify its SHA-256 against that release before installation. Install FastAPI and an ASGI server for the [minimal FastAPI example](examples/fastapi_app/README.md). The successor package's `PublisherConfig` accepts a server Test or production key through `server_key`, exact public origins, saved formats and approved sizes. The older `server_test_key` constructor name remains accepted for existing Test integrations. It rejects browser-selected project or format overrides. GPC suppresses placement and consent changes without blocking the publisher's model generation.

`wavebird_publisher.fastapi.create_app` provides same-origin placement, consent, generation and browser-module routes. The opt-in successor `mount_fastapi` installs those routes in an existing app. Supply the real server-validated session ID and existing abortable model response hooks; the defaults in the example deny or raise. Consent writes and placement/generation turn identity must match that validated session. The package binds one placement and generation to a turn and queues ordered `started`, `finished` or `failed` reports only with a trusted server-side Wavebird job ID. Reporting delay or failure does not hold the publisher's model; verify accepted reports and durable facts independently. The opt-in `turn_journal_path` stores the binding and pending reports in a durable SQLite file shared by workers on one host. The legacy in-memory coordinator remains for existing integrations. Multi-host or serverless deployment needs a separately verified shared-store path.

The wheel also includes a browser host module, served by the FastAPI route at `/api/wavebird/browser.js`. Mount it beside the existing result, connect real session/model/CMP hooks, and pass the saved timing, consent mode and slot height. The server derives its normal width and height envelope from saved `allowed_sizes`; optional `max_width` and `max_height` are advanced caps that can only narrow it. The browser module loads the official `https://api.wavebird.ai/v1/render.js` renderer to display the creative and send its rendering lifecycle. The Python server alone does not render an ad. Keep the model result independent of consent, No-Fill or ad timing. Verify the visible creative, same request/slot reporting and durable nonpayable project fact for each enabled format. Clip additionally needs visible playback and completion evidence.
